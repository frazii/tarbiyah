## Objective

The dashboard's prayer-times section becomes a slim, glanceable **utility strip**
instead of a tall card: the **next prayer is the visual anchor** (large time +
countdown), the remaining four prayers shrink to small secondary chips, the strip's
background subtly reflects the **actual time of day** (day / evening / night,
derived from today's timings), and the **current date and clock** sit beside the
prayer times so a user can cross-check at a glance. Done means: the widget is one
row (~72 px on desktop, wrapping on mobile), reads correctly in all three period
backgrounds at WCAG AA contrast, and the dashboard no longer devotes a full card
with five arch tiles to prayer times.

The dedicated `/prayer-times` page keeps its detailed five-arch grid — this plan
only slims the widget form used on dashboards.

## Current state

`src/components/PrayerTimes.tsx` is a client component that already does the hard
work: geolocation with a Makkah fallback, an AlAdhan `timings` fetch keyed by
center coordinates + calc method, a Hijri date, a 30-second ticker, and a
`nextPrayer` memo (name + minutes until). Today it renders all five prayers as
equal-weight arch tiles inside a `Card` titled "Today's Adhan timings" on both
dashboard variants (`src/app/(app)/dashboard/page.tsx` lines ~53 and ~221) and on
`/prayer-times`.

## Approach

**Reuse:** the fetch, geolocation fallback, `nextPrayer` memo, Hijri string, and
30-second ticker stay exactly as they are. The change is presentational plus one
new derived value.

**New — day period.** Derive `period: "day" | "evening" | "night"` from the
fetched timings and `now`: Sunrise→Asr = `day`, Asr→Isha = `evening`,
Isha→Sunrise = `night` (so pre-dawn Fajr correctly shows the night background).
Recompute in the same memo pass as `nextPrayer`.

**New — sky backgrounds.** Three utility classes in `src/app/globals.css`, built
from existing theme tokens so per-center branding still harmonises:

- `.sky-day` — very soft blue wash (`secondary-soft` → white gradient), ink text.
- `.sky-evening` — warm gold wash (`gold-soft` → `amber-soft`), ink text.
- `.sky-night` — deep gradient (`ink` → `primary-dark`), white/near-white text;
  gold accents stay ≥ 4.5:1 on it (verified in the contrast step).

**New — widget layout.** `PrayerTimes` gains `variant: "widget" | "full"`
(default `widget`; `full` preserves today's arch-tile grid for `/prayer-times`).
The widget is a single rounded strip, one flex row that wraps at small widths:

1. **Clock block** — current time (`3:42 PM`, minute precision), then the
   Gregorian date and Hijri date in small muted text.
2. **Next prayer block** — small "NEXT" label with the Arabic name, the prayer
   name + time in display type (the only large text in the strip), and the
   countdown ("in 23m").
3. **Other prayers** — the remaining four as small name+time chips, pushed to the
   right on desktop, wrapping under on mobile.

**Dashboard placement.** Replace the `Card` + "Today's Adhan timings" heading on
both dashboard variants with the bare widget strip — no card wrapper, no heading;
the strip is self-labelling. It stays where the card is today (below the module
tiles for parents, below stats for staff).

<Callout tone="decision" title="Decisions (12 Jul 2026)">
Night = deep dark gradient with white text. Clock = minute precision, 30 s tick.
The public landing page (`src/app/page.tsx`) also adopts the widget, replacing its
large "Today's Adhan timings" card.
</Callout>

## Risks

- **Night-sky contrast.** White text and gold Arabic on the dark gradient must be
  re-checked with the same WCAG script used for the token audit; adjust the
  gradient's light end rather than the text if a pair fails.
- **Branded centers.** `--color-primary-dark` participates in `.sky-night`, so a
  center brand color changes the night sky. That is intended (subtle brand
  harmony), but a very light brand color could weaken contrast — the existing
  4.5:1 brand-color guard already prevents light brands from being saved.
- **Clock drift.** The 30 s ticker means the clock can lag up to 29 s; acceptable
  at minute precision (see Open Questions).
